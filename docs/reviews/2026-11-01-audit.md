## Project structure / source ownership

- `extension/chrome/` — single canonical Chrome MV3 source and shared behavior.
- `tools/build-ios.mjs` — generates Safari Userscript from canonical Chrome source.
- `src/` — Next.js storefront, authentication, account dashboard, admin and API.
- `supabase/` — migrations, Edge Function source/config and generated Database types.
- `workspace/` — AI hand-off instructions split into shared, Chrome, iOS, Web, Supabase and platform prompts.
- `releases/v2.3.2/` — generated Chrome ZIP and iOS Userscript.
- `archive/legacy-releases/v2.3.1/` — previous package retained for reference, not served by the website.
- `public/downloads/` — only the iOS auto-update Userscript remains public.

The Next.js app and Vercel root stay at the repository root intentionally. The supported `src/` convention moves application code, not `public/`, root environment files or package/Next configuration. Arbitrarily moving those would require changing Vercel Root Directory/build configuration and many paths, adding risk without benefit.

## Changes made

### Extension / program

- Removed Unfollow from UI, relationship state labels, action handling, API providers, storage/rate-limit data, translations and styles. Follow remains the only relationship action.
- States with no available action expose no action label.
- History groups lost followers, lost followers still in Following, accounts missing from both lists, new followers, accounts no longer in Following, and accounts newly present in Following.

## Open findings / real-world acceptance tasks

1. **Real device acceptance:** Chrome extension must still be installed and exercised in desktop Chrome using an authorized Instagram test account. iOS Userscript must still be installed/exercised on a real iPhone/iPad Safari + Userscripts manager. The production Download page was browser-tested; the extension running inside Instagram was not field-tested.
2. **Supabase Auth setting:** Security Advisor reports leaked-password protection disabled. This is an Auth Dashboard setting and remains open; enable and test it before treating auth hardening as complete.
3. **Performance Advisor:** `web_license_secrets_user_id_idx` is currently unused. Keep it for now; the table/index is new and it supports queries by the owner foreign key.
4. **Website checkout:** Stripe checkout remains disabled pending end-to-end payment verification, confirmed product prices, legal/support details and webhook testing.
5. **License mapping:** Chrome web downloads authorize admins or a paid web order tied to the user's active license. Manually issued/externally sold keys are not automatically linked to a website user until that account-linking workflow is designed.
6. **Paid-download branch:** Production was tested without a signed-in paid/admin account. The unauthenticated redirect is verified; successful ZIP streaming for an eligible paid account still requires a controlled authorized account test.

## Security limitations

Customer JavaScript, ZIPs and Userscripts are inspectable and modifiable. Obfuscation cannot make local license checks tamper-proof. License decisions, revocation and privileged database/payment operations must stay server-side. The protected download endpoint gates initial Chrome package delivery, not the secrecy of source code after a customer receives it.

No Instagram account was scanned or modified during this audit.
