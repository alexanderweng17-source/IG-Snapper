## Project structure / source ownership

- `extension/chrome/` — single canonical Chrome MV3 source and shared behavior.
- `tools/build-ios.mjs` — generates the Safari Userscript from canonical Chrome source.
- `src/` — Next.js storefront, authentication, account dashboard, admin and API.
- `supabase/` — migrations, Edge Function source/config and generated Database types.
- `workspace/` — AI hand-off instructions separated into shared, Chrome, iOS, Web and Supabase.
- `releases/v2.3.2/` — generated Chrome ZIP and iOS Userscript.
- `archive/legacy-releases/v2.3.1/` — previous package, retained for audit but not web-served.
- `public/downloads/` — only the iOS update Userscript remains public.

The Next.js app and Vercel root stay at the repository root intentionally. The supported `src/` convention moves application code, not `public/`, root environment files or package/Next configuration. Arbitrarily moving those would require changing Vercel Root Directory/build configuration and many paths, adding risk without benefit.

## Changes made

### Extension / program

- Removed Unfollow from UI, relationship state labels, action handling, API providers, storage/rate-limit data, translations and styles. Follow remains the only relationship action.
- No-action relationship states no longer expose labels that appear to be clickable actions.
- History groups lost followers, lost followers still in Following, accounts missing from both lists, new followers, accounts no longer in Following, and accounts newly present in Following.
- Reworded the History explanations: Instagram does not expose the reason an account disappears. A list difference cannot prove a deliberate unfollow, block, deactivation or deletion.
- Snapshot membership compares stable IDs, ignoring list order and display-name changes.
- Pagination rejects missing/repeated cursors and empty pages while more pages are promised; partial lists are not cached as complete.
- Cache follows the current Instagram viewer ID; TTL is ten minutes; manual Refresh invalidates both lists.
- Fixed Windows CRLF handling in the iOS build tool.

### Web / downloads

- Download Preview now presents separate Desktop and iPhone/iPad install flows.
- Added `GET /api/downloads/chrome`. It requires a valid Supabase user session and either an allowlisted admin or a paid web order linked to an active, unexpired license.
- Next.js output tracing includes the versioned ZIP in the protected serverless route.
- The Chrome ZIP is stored under `releases/`, not `public/`; the old direct ZIP URL returns 404 on the local production server.
- The public iOS Userscript URL remains available for auto-update.
- Website compatibility now says Chrome/iOS are untested on real hardware rather than asserting they have been field-tested.

### Supabase

- Restored the original production migration baseline `20261029020339_licenses_v2.sql` from Supabase migration history.
- Added the deployed `verify-license` Edge Function source, helper and project config.
- Generated `supabase/types/database.types.ts` from production.
- Applied and verified an index on `web_license_secrets.user_id` with migration `20261031191819_index_web_license_secrets_user_id.sql`.
- Supabase `list_migrations` returned the same four versions/names as the local migration folder.
- Inspected SECURITY DEFINER grants: the eight privileged functions are not executable by `anon` or `authenticated`; `service_role` can execute them.
- Did not alter customer orders or license records.

## Open findings / release gates

1. **Real device acceptance:** Chrome extension must still be installed and exercised in desktop Chrome using an authorized test account. iOS Userscript must still be installed and exercised on a real iPhone/iPad Safari + Userscripts manager. Automated builds are not device acceptance.
2. **Supabase Auth setting:** Security Advisor reports leaked-password protection disabled. This is an Auth Dashboard setting and remains open; enable and test it in Auth before treating auth hardening as complete.
3. **Performance Advisor:** the new `web_license_secrets_user_id_idx` is currently unused. Keep it for now; the table/index is new and it supports queries by the owner foreign key.
4. **Website checkout:** Stripe checkout remains disabled pending end-to-end payment verification, confirmed product prices, legal/support details and webhook testing.
5. **License mapping:** web downloads currently authorize admins or a paid web order tied to the user's active license. Manually issued/externally sold keys are not automatically linked to a website user until that account-linking workflow is designed.
6. **GitHub/Vercel:** local history is reconciled to fetched GitHub `main` (local is ahead two commits, behind zero), but the working tree is still dirty. Commit and push the finished changes without force-push, then verify CI and the resulting Vercel production deployment.
7. **Production smoke test:** repeat all download/preview checks on the deployed production domain after deployment.

## Security limitations

Customer JavaScript, ZIPs and Userscripts are inspectable and modifiable. Obfuscation cannot make local license checks tamper-proof. License decisions, revocation and privileged database/payment operations must stay server-side. The new protected download endpoint gates initial Chrome package delivery, not the secrecy of source code after a customer receives it.

No Instagram account was scanned or modified during this audit.
